# 安全设计文档

## 1. 安全设计哲学

### 1.1 核心原则

```
Fail-Safe > Fail-Operational > Performance

任何安全机制触发 → 立即进入安全状态 → 停止推注 → 报警
```

| 原则 | 说明 |
|------|------|
| **默认安全** | 任何异常都应导致"停药"而非"多给药" |
| **纵深防御** | 硬件 + 固件 + 通信, 三层独立防护 |
| **最小权限** | 每个模块只能访问必需资源 |
| **故障可检测** | 所有关键路径必须有异常检测机制 |
| **隔离失效** | 一个模块的故障不应传播到其他模块 |

### 1.2 风险评估矩阵

```
严重性 × 发生概率 = 风险等级

严重性:
  S4 — 致命 (严重低血糖 → 昏迷/死亡)
  S3 — 严重 (低血糖/高血糖需要外部干预)
  S2 — 中等 (轻微血糖异常)
  S1 — 轻微 (临时不适)

概率:
  P5 — 频繁 (每次使用发生)
  P4 — 可能 (每周发生)
  P3 — 偶尔 (每月发生)
  P2 — 罕见 (每年发生)
  P1 — 极罕见 (终生一遇)
```

| 风险场景 | 严重性 | 概率 | 等级 | 缓解措施 |
|----------|--------|------|------|----------|
| 过量推注 | S4 | P2 | 严重 | 硬件限位 + 步数计数 + 独立看门狗 + 电流限制 |
| 推注不足 | S3 | P2 | 高 | 位置编码器 + 压力传感器 + 累积偏差检测 |
| 电池耗尽 | S3 | P3 | 高 | 低电报警 ×2 级 + 自动降功耗 + 关机保护 |
| 储药器泄漏 | S2 | P2 | 中 | 驱动压力监测 + 储药器容量跟踪 |
| 通信中断 | S2 | P3 | 中 | 离线基础率维持 + 通信超时报警 |
| 电机堵转 | S2 | P2 | 中 | 位置变化检测 + DRV8825 故障中断 + INA226 电流监护 |
| 固件崩溃 | S4 | P1 | 严重 | 双看门狗 + 分区回滚 + 安全启动 |
| EMP/静电干扰 | S2 | P1 | 低 | ESD 保护 + 屏蔽外壳 + 屏蔽电缆 |
| 物理损坏 | S3 | P1 | 高 | 防水外壳 + 保险丝 + 撞击后自检 |

## 2. 硬件安全机制

### 2.1 分层防护架构

```
┌──────────────────────────────────────────────────────────┐
│ Layer 4: 物理安全 (外壳/保险丝/限位开关/屏蔽)            │
├──────────────────────────────────────────────────────────┤
│ Layer 3: 硬件保护 (过流/过热/欠压/看门狗 IC)              │
├──────────────────────────────────────────────────────────┤
│ Layer 2: 固件安全 (状态机/CRC/范围检查/WDT)               │
├──────────────────────────────────────────────────────────┤
│ Layer 1: 通信安全 (BLE 加密/协议 CRC/超时)                │
└──────────────────────────────────────────────────────────┘
```

### 2.2 独立硬件保护

#### A. 看门狗 IC (外部)

**型号推荐: TPS3813K33** (或 MAX6369)

```
连接:
  ESP32-C6 GPIO → WDI (看门狗输入)
  WDT RST → ESP32 EN (复位引脚)

参数:
  - 超时时间: 1.6 秒 (TPS3813K33 内部固定)
  - 必须每 < 1.6 秒 翻转 WDI 引脚一次
  - 超时 → 拉低 RST → 硬件复位 ESP32
  - 复位后: DRV8825 nRESET 也被拉低 → 电机停止
```

**关键设计**: 外部 WDT 独立于 ESP32 内部 WDT, 即使 ESP32 完全死锁也能强制复位。

#### B. 限位开关 (硬件终点)

```
物理限位: 微动开关 (Omron D2F)
- 前进限位: 防止推杆超出最大行程
- 后退限位: 防止推杆撞到电机本体

连接:
  限位 NC → ESP32 GPIO (上拉) → 分压器 → DRV8825 nENABLE
                 ↓
          (GPIO 可读)              (硬件直连)

  当限位触发:
    1. GPIO 读到 LOW → 固件立即停止 STEP
    2. 同时拉高 nENABLE → 硬件禁用电机驱动
  (双路径: 固件 + 硬件, 任意一条生效即可停止)
```

#### C. 电机电流限制

DRV8825 内置保护:
| 保护类型 | 阈值 | 动作 |
|----------|------|------|
| 过流 (OCP) | 2.5A | 关闭 H 桥 |
| 过热 (TSD) | 160°C | 关闭驱动 |
| 欠压 (UVLO) | 8.2V | 重置驱动 |
| nFAULT 输出 | 任何以上故障 | 拉低 → ESP32 检测 |

#### D. 电池保护板 (BMS)

```
3S BMS 板功能:
  - 过充保护: 4.25V ± 0.05V / cell (总 12.6V)
  - 过放保护: 2.50V ± 0.10V / cell (总 7.5V)
  - 过流保护: 3.0A ± 1.0A
  - 短路保护: < 100µs 响应
  - 均衡充电: 4.20V ± 0.03V

推荐: IP3002 + HY2213 方案 (支持 2-3S)
```

#### E. INA226 电流/电压监测（Rev.2 新增）

INA226 串接在 11.1V 母线与电机回路之间（20mΩ 分流），以 I2C 向 ESP32-C6 上报总线电压、分流电流与功率：

```
安全用途:
  - 丢步检测: 电机运转中电流持续 < 80mA → 未带载/丢步 → ALARM_STEP_LOSS
  - 堵转检测: 电流持续 > 700mA → 机械阻塞 → 停止推注
  - 过流检测: 总电流 > 1A → ALARM_OVER_CURRENT
  - 原点监护: 手动微动 (KEY_UP/DOWN) 期间实时显示电流，辅助判定咬合状态
  - 充电识别: 电流方向为负 (放电电流 < -50mA) → 判定为充电中
```

INA226 独立于 ESP32 ADC，精度 ±1%，可在电机运动期间以 5ms 间隔采样，构成固件层丢步/堵转判定的数据来源（详见 docs/03-motor-drive.md §8）。

## 3. 固件安全机制

### 3.1 安全状态机

```
                    ┌───────────────────────────┐
                    │       ALL STATES           │
                    │  [持续监控安全条件]        │
                    └──────────┬────────────────┘
                               │ 任何异常
                               ▼
                    ┌───────────────────┐
                    │   SAFE STATE      │
                    │                   │
                    │ • 电机禁用        │
                    │ • 基础率停止      │
                    │ • 报警激活        │
                    │ • 等待手动确认    │
                    └───────────────────┘
```

**规则**:
1. 从任何状态可以进入 SAFE STATE
2. 从 SAFE STATE 只能通过显式清除报警退出
3. 退出 SAFE STATE 后必须先经过 IDLE 状态

### 3.2 安全检查清单 (每 1 秒执行)

```cpp
void safety_check_cycle() {
    // 1. 电池: < 临界阈值 → ALARM_BATTERY_CRITICAL (3S: 9.0V)
    // 2. 储药器: == 0 → ALARM_RESERVOIR_EMPTY
    // 3. 限位: 触发 + 正在运动 → ALARM_LIMIT_TRIGGERED
    // 4. nFAULT: LOW → ALARM_MOTOR_FAULT
    // 5. 通信: BLE 断连 > 5min → ALARM_COMM_LOST
    // 6. 温度: > 60°C → ALARM_OVER_TEMP
    // 7. 电流: INA226 总电流 > 1A → ALARM_OVER_CURRENT
    // 8. 堵塞: 推注中位置不变 → ALARM_OCCLUSION
    // 9. 丢步: INA226 电机电流异常 → ALARM_STEP_LOSS (Rev.2 新增)
}
```

### 3.3 双重计数保护

每次推注使用**双重独立计数**防止单次故障导致过量:

```
方法 1: RMT 脉冲计数 (硬件计数)
  - ESP32 RMT 外设在发送脉冲时硬件计数
  - 发送完成后对比: 实际发送 == 预期发送?

方法 2: GPIO 翻转计数 (软件 ISR 计数)
  - GPIO 中断在每次 STEP 引脚上升沿时递增计数器
  - 与 RMT 计数交叉验证

如果两者不一致 > 1% → ALARM_OVERFLOW → 紧急停止
```

### 3.4 指令范围检查

所有来自 BLE/USB 的命令都必须通过:

```cpp
// 大剂量上限检查
if (requested_bolus > config.max_bolus_per_hour) {
    reject_command();
    trigger_alarm(ALARM_OVERFLOW);
}

// 基础率上限检查
if (requested_rate > config.max_basal_per_hour) {
    reject_command();
}

// 单次最大步数检查
if (requested_steps > MAX_CONTINUOUS_STEPS) {
    split_into_chunks();  // 分块执行, 每块后有安全检查
}

// CRC 校验
if (calculate_crc(payload) != received_crc) {
    reject_command();
}
```

### 3.5 看门狗策略

```
┌──────────────┐
│ 外部 WDT IC  │ ← 1.6s 超时, 硬件复位
│ (TPS3813)    │
└──────┬───────┘
       │
┌──────┴───────┐
│ ESP-IDF IWDT │ ← 中断级看门狗 (约 5s)
│ (Interrupt)  │
└──────┬───────┘
       │
┌──────┴───────┐
│ ESP-IDF TWDT │ ← 任务级看门狗 (各任务独立, 10s)
│ (per-task)   │
└──────────────┘

恢复流程:
  IWDT 触发 → panic → 记录 coredump → 重启 → 验证配置 → 恢复基础率
  TWDT 触发 → 杀死违规任务 → 重建任务 → 恢复执行
  外部 WDT 触发 → 全板硬件复位 → 从初始状态启动 → 不恢复自动给药
```

### 3.6 OTA 安全

```
下载固件
   ↓
验证 HTTPS 证书 (mbedTLS)
   ↓
验证固件签名 (ECDSA P-256)
   ↓
验证固件版本 > 当前版本 (防回滚)
   ↓
验证 SHA-256 校验和
   ↓
写入 OTA 分区
   ↓
验证新分区完整性
   ↓
设置启动分区标志
   ↓
重启
   ↓ (如果新固件崩溃 3 次)
自动回滚到旧版本 (ESP-IDF 内置防变砖)
```

## 4. 通信安全

### 4.1 BLE 安全层级

```
Level 0: Just Works (默认, 开发测试用)
  - 无 PIN, 无 MITM 保护
  - 适用范围: 可信环境

Level 1: Passkey Entry (推荐)
  - 6 位 PIN 码, 显示在 1.47" LCD 上
  - MITM 保护
  - 适用范围: 日常使用

Level 2: Numeric Comparison + Bonding
  - 双方确认 6 位数字一致
  - 绑定后可自动重连
  - 适用范围: 首次配对后无需 PIN
```

### 4.2 GATT 协议安全

| 特征 | 权限 | 加密要求 |
|------|------|----------|
| Device Info (0x180A) | Read | 无需加密 |
| Battery Level (0x2A19) | Read | 无需加密 |
| **Bolus Command** | Write | **AES-CCM 加密** |
| **Basal Schedule** | Write | **AES-CCM 加密** |
| **TBR Command** | Write | **AES-CCM 加密** |
| Pump Status | Read+Notify | 无需加密 (读) |
| IOB | Read+Notify | 无需加密 (读) |
| Reservoir | Read+Notify | 无需加密 (读) |

**所有写操作使用 CRC-8 校验**, 匹配失败则拒绝命令。

### 4.3 BLE 连接超时策略

```
连接正常: 维持闭环模式
断连 < 1 分钟: 维持最后基础率
断连 1-5 分钟: 维持最后基础率 + 每隔 1 分钟蜂鸣提醒
断连 > 5 分钟: 维持最后基础率 + 连续报警 (ALARM_COMM_LOST)
断连 > 30 分钟: 切换到内置安全基础率 (0.5 U/h)
```

## 5. 报警分级

| 级别 | 编码 | 蜂鸣 | LED | 动作 |
|------|------|------|-----|------|
| 提醒 | 低电 / 临近换药 | 每 5s 短鸣 | 黄灯闪 | 仅通知, 不中断 |
| 警告 | 储药器空 / 通信中断 | 每 1s 短鸣 | 红灯闪 | 停止大剂量, 维持基础率 |
| 严重 | 阻塞 / 电机故障 | 连续急促 | 红灯常亮 | 立即停止一切推注 |
| 致命 | 固件崩溃 / WDT 复位 | 持续蜂鸣 | 全黑 | 硬件复位, 不自动恢复 |

### 5.1 报警确认

- **提醒级别**: APP 一键清除
- **警告级别**: APP 确认 + 物理按钮确认
- **严重级别**: 必须检查物理泵状态 + 手动清除
- **致命级别**: 需要重启泵

## 6. 故障注入测试清单

在开发过程中应通过以下方式验证安全机制:

| 测试 | 注入方法 | 预期结果 |
|------|----------|----------|
| 电机堵转 | 物理阻塞推杆 | ALARM_OCCLUSION, 停止电机 |
| BLE 断开 | 关闭手机蓝牙 | 5 分钟后 ALARM_COMM_LOST |
| BLE 恶意命令 | 发送超大 bolus 值 | 范围检查拒绝, 不执行 |
| BLE 损坏包 | 发送错误 CRC 的命令 | CRC 不匹配, 拒绝 |
| 电池过放 | 用可调电源降至 8.0V | ALARM_BATTERY_CRITICAL → 停机 (3S 体系) |
| 限位触发 | 手动运行到尽头 | 硬件 + 固件双停止 |
| 看门狗超时 | 在安全任务中死循环 | 外部 WDT 复位 |
| DRV8825 过热 | 用热风枪加热 | nFAULT 触发 → 报警 |
| OTA 损坏固件 | 发送 SHA 错误的固件 | 验证失败, 不安装 |
| 电磁干扰 | 用打火机靠近电路 | 无异常 (验证屏蔽) |

## 7. 安全认证参考

本设计参考以下标准:
- **IEC 60601-1**: 医疗电气设备基本安全 (绝缘、漏电流)
- **IEC 60601-1-2**: 电磁兼容性 (EMC)
- **IEC 62304**: 医疗设备软件生命周期 (A/B/C 三级)
- **ISO 14971**: 医疗器械风险管理

> 注意: DIY 项目不必取得正式认证, 但设计应符合以上标准的精神。使用者需自行承担风险。
